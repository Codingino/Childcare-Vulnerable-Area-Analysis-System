# 이음 v2 연구 설계: 도움 뒤의 관리 부담까지 보기

조사일 2026-09-07. 최신 근거·표본·한계·링크는 [근거 조사 기록](EVIDENCE-2026.md)에 정리했다. 실제 앱 효과 데이터는 아직 없다.

## 기존 탐구와 이어지는 질문

기존 연구: 생활권 내 어린이집의 수·정원·현원·국공립 정원 비율로 보육 취약 가능성을 탐색했다.

후속 질문: **보육 정보를 찾고 도움을 구하는 과정에서 생기는 부모의 인지적 부담을, 요청 범위와 완료 기준을 명시한 작은 도움 연결이 덜어줄 수 있는가?**

공급 여건 → 정보·도움 필요 → 도움 요청 → 연결 및 완료 → 여전히 남는 확인 부담의 경로를 탐색한다. 이 경로는 가설이며 기존 지역 지표만으로 개인의 고립·우울증을 예측하지 않는다.

추천 발표 제목: **보육 접근성 분석에서 부모의 인지적 부담 완화 실험으로: 부탁 구조화와 응답 방식 선택을 적용한 생활 지원 앱 운영**.

## v1에서 바꾼 이유

v1의 '10분 도움 게시판'은 기존 커뮤니티와 겹쳤고, 무엇을 어떻게 부탁할지 생각하는 일을 요청자에게 남겼다. v2는 혼자서도 바로 쓸 수 있는 부탁 카드가 출발점이다. 가입 장벽은 없애되 다른 사람의 글·연구 기록에 접근하는 계정 권한은 유지했다.

| 비교 대상 | 겹치는 점 | v2의 선택 |
|---|---|---|
| 육아크루/Peanut | 부모 친구·대화·모임 | 인맥을 만들기 전에 구체적인 부탁 하나 정리 |
| 베이비빌리 | 정보·커뮤니티 | 더 많은 콘텐츠보다 찾을 범위·확인할 결과를 제한 |
| Fair Play | 보이지 않는 일과 책임 분담 | 가족 내 역할 관리 전체 대신 부모의 작은 정보·교류 요청에 적용 |
| TimeBanks | 도움 교환 | 상환 포인트·순위 없음 |
| 복지로/아이사랑/가족센터 | 공식 정보·지원 | 원문으로 연결하고 함께 찾는 과정을 지원 |

독창성은 결합과 검증 방식의 가설이다. 기능의 세계 최초성이나 경쟁사 부재를 주장하지 않는다.

## 실제 구현과 측정 구분

- 기기 카드: 부탁 내용·원하는 응답·완료 기준을 작성/수정해 기기에 저장. 다른 사용자나 서버에 자동 전송하지 않는다. 직접 공유 또는 공동체 게시를 선택한다.
- 공동체 카드: 들어주기/정보 정리/함께하기 + 제안 시간 2/5/10분. 범위는 짧게, 완료 조건은 분명히. 검토 후 공개 → 1명 응답 → 요청자가 실제 완료 확인.
- 선택적 결과 문항: 원하던 응답이었는가(예/아니요), 신경 쓰임이 줄었는가(1~5), 다시 챙기거나 확인해야 했는가(예/아니요).
- 기존 주간 설문: 정보 탐색 부담·도움 요청 가능성(1~5), 정보 탐색 시간·실제 도움 횟수.
- 위 문항은 모두 자체 문항이다. 검증된 심리척도로 부르지 않는다. 초단기 평가를 우울증·소진의 치료 효과로 바꾸지 않는다.

기기 카드 숫자는 본인이 작성/완료 표시한 건수다. 사회적 도움 건수나 절약 시간으로 자동 환산하지 않는다. 로그인하지 않은 기기 이용은 연구 서버에 추적되지 않으므로 서버 가입/활동 수와 다르다.

## 6~8주 파일럿

1. 준비 1~2주: 성인 공동운영자·지도교사, 문의 창구, 데이터 보관/삭제 절차를 확정한다. 국내 영유아 보호자 5~8명에게 카드 문구와 입력 부담을 점검한다. 실제 인터뷰는 아직 수행하지 않았다.
2. 모집: 우선 20~30명. 직접 가입을 허용하므로 모집 수·중복 가입 가능성·실제 대상 여부를 운영일지로 확인한다. 앱 가입 상한은 50계정이며 50명의 검증된 서로 다른 사람을 뜻하지 않는다.
3. 기준 주: 사용 전 주간 설문을 받고 다음 UTC 주차부터 운영한다. 한 주 한 응답이므로 같은 주에 사전·사후를 받지 않는다.
4. 운영 4~6주: 게시물·답글 검토, 무응답 요청 확인, 장애·운영자 시간·철회/삭제 수 기록. 앱이 일을 늘리는지 확인한다.
5. 종료: 주간 응답의 최초~최종 변화를 짝지어 기술. 완료율·미해결 요청과 선택 문항 무응답도 함께 보고한다. 같은 사람이 여러 요청을 쓴 가중 효과를 확인한다.

## 주요 지표와 분모

| 지표 | 분모·정의 | 한계 |
|---|---|---|
| 7일 연결률 | 생성 후 7일 이상 관찰된 연구 대상 요청 중 7일 내 연결된 비율 | 검토 대기 시간을 포함. 응답 취소 후 재연결은 현재/최종 연결 시각 |
| 7일 완료율 | 위 분모 중 7일 내 요청자 완료 | 자기보고. 실제 시간 절감과 다름 |
| 응답 시간 중앙값 | 7일 내 연결된 요청의 생성~연결 | 무응답을 제외하므로 미연결 수를 함께 제시 |
| 응답 적합성 | 완료 후 fit에 응답한 요청 중 '예' | 선택 응답 편향. 글 내용 평가를 자동 수행하지 않음 |
| 추가 확인 부담 | 완료 후 followup에 응답한 요청 중 '예' | 필요한 정상 확인도 포함 가능 |
| 신경 쓰임 변화 | 완료 후 relief 1~5 평균 | 임상 척도 아님. 요청 단위로 가중됨 |
| 주간 변화 | 최소 2주 응답한 동일 계정의 최초·최종 차이 | 기간·이탈·회상오차·상한 절단 |

`analyze.py`는 해당 평균·비율의 응답자가 5명 미만이면 값을 표시하지 않는다. 지역×응답 방식 교차표 등의 소수 집단은 별도 공개하지 않는다. 게시물 삭제·철회로 분모에서 빠지는 생존자 편향이 존재한다. 삭제를 무효화하려 원본을 따로 보존하지 않는다.

## 비교 실험으로 확장하려면

v2와 v1의 단순 시기 비교에는 계절·참여자·운영 숙련의 차이가 섞인다. 첫 기수는 사용성·실행 가능성을 우선 보고하고, 이후 충분한 참여자를 모집한 경우 '자유롭게 작성'과 '완료 기준을 함께 작성'의 순차 또는 무작위 배정을 별도 프로토콜로 검토한다. 현재 앱에는 자동 무작위 배정이나 A/B 실험이 없다. 사전·사후 기술통계만으로 인과 효과를 주장하지 않는다.

## 지역 데이터 연결의 현실적 범위

현재 직접 가입자는 하나의 '열린 이웃' 공동체에 들어간다. 위치를 수집하거나 자동 지역 매칭을 하지 않는다. 기존 v1의 별도 모임은 계정 전환 시 그대로 분리 유지된다. 따라서 v2의 기본 서버 데이터만으로 지역 간 효과를 비교할 수 없다.

지역 비교가 필요하면 사전 동의를 받은 모집 단위와 공공데이터를 별도 연구 절차로 연결해야 한다. `context.py`는 생활권의 영유아 1,000명당 정원, 정원 가중 충원율, 국공립 정원 비율과 40/40/20·50/30/20·30/50/20 가중치 점수를 계산한다. 실제 집 주소는 입력하지 않는다. 연령 범위와 기준일이 맞는 분모를 사용한다.

기존 보고서에서는 국공립 시설 수 비율/정원 비율 설명과 주소 검색 실패 설명이 혼재한다. GitHub의 child.py는 정원 가중 방식을 쓰지만 검색 결과가 없을 때 기본 위치를 반환하는 경로가 남아 있다. 기존 지표를 사용할 때 이를 확인한다. 이번 변경은 기존 분석 코드를 바꾸지 않는다.

## 발표에서 보여줄 것

문제 발견 → 근거의 강도와 한계 → 기존 모델과의 차이 → v1에서 남은 부담 → v2 설계 → 실제 모집·사용·미해결·이탈 → 운영 때문에 고친 점 → 다음 실험.

사회적 의의는 검증되지 않은 큰 효과가 아니라, **부모에게 새로운 일을 더하지 않는 도움 방식이 가능한지 실제로 점검했다는 과정**에서 나온다.
