# 이음: 시장 비교와 후속 탐구 설계

조사일: 2026-09-07. 공식 서비스 소개와 운영기관 안내를 검토한 문헌·서비스 조사다. 앱을 모두 설치해 전 기능을 실측한 조사는 아니며 시장점유율·정확한 이용자 수·효과 크기를 검증하지 않았다. 아래 차별성은 제품 설계 가설이지 독점성이나 최초성 주장이 아니다.

## 1. 판단: 탐구로는 적합, 전국 종합 육아 앱으로 출발하는 것은 비추천

기존 탐구는 어린이집 위치·정원·현원·국공립 비중을 이용해 보육 접근성의 차이를 탐색했다. 그 다음은 공급 지표를 더 만드는 데서 멈추지 않고, 부모가 실제로 겪는 어려움을 확인하고 작은 개입을 운영해 보는 단계가 될 수 있다. 다만 어린이집 부족 → 부모 고립 → 우울증이라는 인과관계를 기존 자료만으로 확정할 수 없다. 연구 대상을 어린이집과 영유아 부모로 일관되게 쓰고 유치원과 혼용하지 않는다.

권장 제목: **보육 접근성 분석에서 생활 지원 실험으로: 초대형 부모 공동체의 소규모 도움 연결과 정보 탐색 부담 변화**.

기존 보고서에서 보완할 점:

- 충원율은 실제 대기 시간·연령별 입소 가능성이 아니다.
- 국공립 '시설 수 비율'과 '정원 비율' 설명이 혼재한다. 후속 비교에서는 국공립 정원/전체 정원으로 통일하고 분모를 공개한다.
- 주소 변환 실패 시 중단한다는 코드 설명과 기본 좌표를 쓴다는 한계 설명이 충돌한다. GitHub 최신 child.py에서는 검색 결과가 없을 때 DEFAULT_LOCATION을 반환하는 경로가 남아 있고 예외 때만 중단한다. 실제 코드와 일치하게 보고서를 고쳐야 한다. 이번 앱은 상세 주소를 받지 않는다.
- 40/40/20 가중치와 임계값은 자체 가정이다. 순위 변화가 있는지 민감도 분석을 한다.
- 시설 공급에서 부모의 개인 상황으로 넘어가므로 집단 자료를 개인의 상태로 해석하는 생태학적 오류를 피한다.

## 2. 이미 있는 서비스와 비교

| 서비스 | 공식 소개에서 확인한 기능 | 겹치는 지점 | 이음의 설계 선택 |
|---|---|---|---|
| 육아크루 | 동네 육아친구, 모임, 정보 공유 | 지역 공동체는 이미 구현됨 | 친구 매칭보다 범위가 작은 도움 요청과 완료 확인을 중심에 배치 |
| 베이비빌리 | 시기별 정보, 커뮤니티, 쇼핑 | 육아 정보·커뮤니티 결합은 흔함 | 상품 추천을 초기 핵심 흐름에 넣지 않음 |
| Peanut | 부모 친구 찾기, 대화, 경험·조언 | 부모 고립에 대응하는 커뮤니티도 기존 모델 | 가입·친교의 결과보다 미해결 요청까지 포함한 실제 연결 과정을 관찰 |
| TimeBanks.Org | 도움을 제공한 시간만큼 시간 크레딧 획득 | 도움 교환 자체는 새롭지 않음 | 도움받을 여력을 갚는 의무·잔액·순위 없이 참여 |
| 아이사랑 | 시설 검색과 공식 등록대기 안내 | 시설 검색 중복 가능 | 공식 서비스로 연결, 입소 가능 여부를 대신 판단하지 않음 |
| 복지로 | 복지서비스 검색·신청·모의계산·복지멤버십 | 지원금 안내 중복 가능 | 공식 원문 연결 + 정보 찾기를 함께 해주는 도움 요청 |
| 가족센터 공동육아 프로그램 | 지역별 공동육아나눔터·품앗이 등 | 오프라인 상호 지원과 겹침 | 지역 운영자·모집 협력 후보. 협약이나 도입은 아직 없음 |

경쟁사가 같은 기능을 제공하지 않는다고 단정하지 않는다. 이음의 차별점은 **작은 도움 단위 + 보답 의무 없음 + 미해결 요청 우선 노출 + 실제 완료 확인 + 연구 동의 분리**의 조합이다.

## 3. 추가한 핵심 기능: 10분 도움

부모가 '친구 만들기'라는 큰 과제를 수행하기 전에 구체적인 작은 부탁을 할 수 있도록 한다.

1. 지원정보 같이 찾기 / 10분 이야기 / 보호자 동반 산책 중 선택해 요청한다.
2. 운영자가 글을 확인하면 같은 초대 모임에 공개한다. 미연결 요청은 오래된 순으로 먼저 보인다.
3. 이웃 한 명이 응답한다. 중복 응답은 서버에서 막는다. 응답자는 취소할 수 있다.
4. 게시물 답글로 내용을 조율한다. 모든 답글은 운영자 확인 후 보인다. 따라서 실시간 상담 앱이 아니며 즉각적인 대화에는 제약이 있다.
5. 요청자가 실제 도움을 받은 경우 완료 처리한다. 응답과 완료를 따로 저장한다.
6. 7일이 지나면 새 응답을 받지 않는다. 기존 연결은 마무리할 수 있다. 글 삭제로 요청을 취소할 수 있다.

'10분'은 작은 참여 부담을 나타내는 제안 시간이며 실제 대화 시간을 자동 측정하거나 응답 시간을 보장하지 않는다. 아이를 다른 이용자에게 맡기는 돌봄 중개, 가정 방문, 유료 거래는 첫 버전에서 제외한다. 산책은 보호자가 각자 아이를 돌보는 형태이며 일정·장소는 운영자가 공공장소 기준으로 조율한다.

다음 후보 기능은 **도움 공백 지도**다. 개별 주소나 사람을 표시하는 대신, 충분한 수가 쌓인 모임 단위에서 '어떤 부탁이 오래 미해결로 남는가'를 기존 보육 공급 자료와 비교한다. 작은 표본에서는 지도 색칠이 과도한 확신을 줄 수 있어 이번 버전은 원본 CSV와 소표본 비표시 분석부터 구현했다. 위치 기반 자동 매칭이나 인공지능 상담은 구현하지 않았다.

## 4. 무엇을 검증할 것인가

주 질문: 작은 도움 요청 방식이 실제로 사용되며, 참여 전후 정보 탐색 부담과 도움 요청 가능성이 어떻게 달라지는가?

부 질문: 생활권의 보육 접근성 지표와 요청 유형·미해결 양상 사이에 탐색적 관련성이 있는가?

| 지표 | 정의 | 주의점 |
|---|---|---|
| 7일 연결률 | 게시 후 7일 안에 응답자가 연결된 요청 / 게시 후 7일 이상 관찰한 요청 | 무응답을 분모에 반드시 포함 |
| 7일 완료율 | 게시 후 7일 안에 요청자가 완료한 요청 / 같은 분모 | 자가 보고이며 효과 입증은 아님 |
| 응답 시간 중앙값 | 연결된 요청의 게시~응답 시간 | 무응답은 별도 수량 병기, 운영자 검토 시간 포함 |
| 정보 탐색 부담 | 지난 7일 부담, 1~5점 | 자체 문항, 임상척도 아님 |
| 도움 요청 가능성 | 필요할 때 도움 요청할 사람이 있었는가, 1~5점 | 사회적 고립의 임상 판정 아님 |
| 정보 탐색 시간 | 지난 7일 총 분, 0~600 | 회상오차·상한 절단 있음 |
| 도움받은 횟수 | 지난 7일 앱에서 실제 도움받은 횟수 | 앱 완료 건수와 차이를 따로 설명 |

응답 취소 후 재연결하면 최종 연결 시간이 저장되므로 '최초 응답 시간'이 아니라 **현재/최종 연결까지의 시간**이다. 삭제·동의 철회된 요청은 연구에서 빠지므로 생존자 편향이 있다. 운영 시 주간 삭제·철회 건수는 개인 식별 없이 운영일지에 적는다. 원본을 보존해 철회를 무력화하지 않는다.

## 5. 6~8주 운영안

- 준비 1~2주: 지도교사와 성인 공동운영자 선정, 모집 안내·문의 연락 창구 확정, 부모 5~8명 인터뷰로 '최근 도움을 못 구한 구체적 상황' 조사. 서비스 데모나 가상 기록을 실제 조사 결과로 사용하지 않는다.
- 모집: 1~2개 생활권, 성인 보호자 20~30명. 모임별 코드로 구분한다. 플랫폼 상한은 총 50명. 접속 코드와 실명 대응표를 연구 CSV와 함께 보관하지 않는다.
- 시작 주: 사용 전 설문을 먼저 받고 다음 주부터 도움 기능을 사용한다. ISO 주차별 한 번 저장하므로 같은 주에 사전·사후를 함께 받지 않는다.
- 운영 4~6주: 주간 설문, 매일 2회 게시물 검토, 무응답 요청 확인. 독려 횟수·운영자 노동시간·장애·신고를 기록한다. 운영자가 대신 도움을 제공한 경우 운영일지에 별도로 표시한다.
- 종료 1주: 동일 문항, 유지율과 이탈 인원 확인, 동의자 CSV 추출, 최소 5명 이상 짝지어진 응답에서 최초~최종 차이를 기술한다. 비교 기간이 사람마다 다를 수 있으므로 기간 분포도 확인한다.
- 가능하면 이후 기수에서 대기군 또는 순차 도입을 검토한다. 이번 단일군 사전·사후 결과만으로 인과 효과를 주장하지 않는다. 표본이 작으면 유의확률보다 사례·분포·한계를 중심으로 발표한다.

20~30명은 모집·관리 가능성을 위한 목표이지 통계적 검정력 계산 결과가 아니다. 다른 지역으로 일반화할 수 없다. 응답자가 적으면 '효과가 없었다'가 아니라 '추정하기 어렵다'고 쓴다. 우울증·자살위험·진료정보는 수집하지 않는다.

## 6. 기존 공공데이터와 연결

운영자는 사전에 선정한 생활권별로 기존 프로그램의 반경·기준일·시설 수·정원·현원·국공립 정원을 기록한다. 개인 집 주소를 수집하거나 부모 개인에게 취약도 낙인을 부여하지 않는다. `context.py`는 생활권 집계 CSV에서 영유아 1,000명당 정원, 정원 가중 충원율, 국공립 정원 비율, 자체 지수 가중치 민감도를 계산한다. GitHub 최신 child.py도 정원 가중 충원율과 국공립 정원 비율을 사용한다. 보고서의 단순 평균 표현과 실제 코드의 차이를 명시한다. 영유아 인구의 기준일·연령 범위가 맞지 않으면 비교하지 않는다.

모임별 표본이 5명 미만이면 지역별 결과를 공개하지 않는다. 지역 수가 1~2개라면 지역 간 효과 차이는 사례 비교로만 다룬다. 공급 지표는 부모의 실제 지원망·소득·근로시간을 대체하지 않는다.

## 7. 발표 구성

문제의식 → 기존 보육 접근성 분석 및 한계 → 경쟁서비스 비교 → 작은 도움이라는 설계 가설 → 구현·운영 방식 → 실제 모집·활동·이탈 데이터 → 변화와 미해결 요청 → 표본·측정·선택편향 → 다음 개선.

'앱을 만들었다'보다 '어떤 가정을 세웠고, 운영 데이터 때문에 무엇을 고쳤는가'가 탐구의 핵심이다. 아직 실제 이용자와 효과 데이터는 없다.
