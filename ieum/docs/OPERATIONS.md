# 파일럿 운영·비용·개인정보

## 제품 범위와 비용

Python + SQLite + 정적 HTML/CSS/JS. 로컬 시험은 추가 서비스 가입 없이 가능하다. 실제 여러 부모의 휴대폰에서 접속하려면 HTTPS 도메인과 영속 디스크가 있는 서버가 필요하다. GitHub에 소스를 올리는 것과 앱을 배포하는 것은 다르며 GitHub Pages만으로 Python 서버가 실행되지 않는다.

초기에는 20~30명, 최대 50명, 글 1인 하루 5개·답글 10개, 텍스트만 허용한다. 이미지·영상 업로드·지도 API·생성형 AI·실시간 채팅을 넣지 않아 외부 호출 과금이 없다. 저장·트래픽 비용이 전혀 없다는 뜻은 아니다. SQLite는 단일 서버에 두며 여러 서버로 수평 확장하지 않는다. DB는 리포지토리·일회성 파일시스템에 두지 않는다.

예산 시나리오(판매자의 가격표가 아닌 운영 상한 예시): 서버·백업 월 10,000원, 도메인 월 환산 2,000원, 예비비 3,000원으로 월 15,000원 이하 목표. 실제 공급자 견적·세금·영속 디스크·트래픽을 배포 전에 확인한다. 해당 비용으로 운영 가능하다고 보장하지 않는다. 주간 사용량과 청구 내역을 보고 예산 80%에서 신규 모집을 멈춘다. 앱에는 공급자 결제 차단 기능이 없으므로 공급자 콘솔에서 한도·알림을 설정해야 한다.

텍스트 저장 예시: 30명 × 하루 2건 × 2KB × 30일 = 본문 약 3.6MB. 색인·DB·백업·페이지 트래픽은 별도다. 운영자 하루 20분 × 30일 = 월 10시간이며 모집·분쟁 대응은 추가다. 이것이 금전 비용보다 먼저 문제가 될 수 있다.

## 수익 구조: 파일럿에서는 무료

1. 파일럿은 학교 프로젝트 예산 또는 소액의 자발적 후원으로 검증한다. 후원·지원 확보 사실은 아직 없다.
2. 유용성이 확인되면 가족센터 등 기관에 '모임 개설·검토·운영 도구' 사용료 모델을 인터뷰로 검증한다. 개인별 데이터 판매가 아니라 운영 도구 제공이다. 계약·조달 가능성은 별도 확인이 필요하다.
3. 추후 지역 후원 배너를 넣더라도 광고임을 표시하고 지원정보·도움 요청 순위를 구매할 수 없게 한다. 현재 결제·광고·후원 수납 기능은 구현하지 않았다.

손익 예시는 고정비 15,000원일 때 월 순후원 3,000원 5건이 단순 서버비를 충당한다는 산술일 뿐이다. 수수료·노동시간·이탈은 포함하지 않으므로 사업성 증거가 아니다. 건강·외로움 기반 타깃 광고, 게시물 판매, 도움 요청 유료화는 목표와 충돌한다.

## 운영 준비

성인 공동운영자와 지도교사를 정하고 안내문에 실제 운영자 이름·문의 수단·보관 기간·종료 일정을 확정한다. 학생 혼자 24시간 대응하는 방식은 피한다. 연구 동의 화면은 준비된 초안이며 학교 연구 검토와 실제 운영 조건에 맞게 확인해야 한다. 법률 준수를 자동 보장하는 문서가 아니다.

서버 배포 전 HTTPS 리버스 프록시, 영속 디스크, 접근 권한, 방화벽, 요청 수 제한, 백업·삭제 일정, 장애 대응자를 설정한다. 공개 인터넷에 개발용 `wsgiref` 서버를 직접 노출하지 않는다. 예시 production 명령은 README에 있다. 업로드·대화 속도가 중요한 대규모 공개 서비스 수준의 검증은 하지 않았다.

초대 코드는 256비트 난수이며 서버에는 SHA-256 해시만 저장한다. 브라우저에는 탭 세션 동안 코드가 남으므로 공용 기기에서는 반드시 나간다. 코드를 아는 사람이 계정을 사용할 수 있다. 코드를 잃거나 유출한 경우 기존 계정을 운영자가 삭제하고 새 초대를 발급한다. 실명 복구·이메일 인증·자동 알림 기능은 없다.

## 매일 할 일

- `python server.py review`로 대기 글·답글·신고 확인. 출력에는 이용자 게시 내용이 있으므로 화면 공유·공개 로그에 남기지 않는다.
- 광고·연락처·아이 이름·가정 주소·위험한 조언이 없는 경우에만 승인. 승인 후에도 신고되면 재검토 대기로 바뀐다. 신고는 모임 내부에서만 가능하다.
- 의료·위기 상황을 게시판에서 해결하려 하지 말고 실제 담당 기관·긴급 대응 체계로 연결한다. 앱을 긴급 상담 창구로 안내하지 않는다.
- 48시간 이상 미응답은 운영자가 확인하고 공식 지원 경로를 안내한다. 자동 알림은 없으므로 운영일지에 기록한다.
- `python server.py purge`를 매일 실행하도록 작업 스케줄러 설정. 가입 90일이 지난 계정과 연결 데이터를 삭제한다. 종료 시 더 이른 삭제 일정을 적용할 수 있다.
- 별도 CSV·백업에도 철회·삭제 요청을 적용한다. 백업을 복구하면 삭제 요청을 재적용한다. 민감한 원본은 GitHub·공개 발표 자료에 올리지 않는다.

## 데이터와 분석

연구 비동의자도 서비스용 글·답글·연결 상태가 필요하다. 연구 동의는 추가 설문·링크 기록과 연구용 도움 CSV 추출에 관한 별도 선택이다. 도움 요청은 생성 시 동의한 것만 연구 대상이며, 철회하면 영구적으로 연구 제외된다. 재동의해도 과거 요청이 자동 복원되지 않는다. 연구 CSV에는 글 본문·실명·주소·응답자의 식별자를 포함하지 않는다. 무작위 ID로 종단 연결이 가능하므로 완전한 익명은 아니다.

설문은 UTC ISO 주차 기준 1인 1건. 한국 시간의 월요일 초반과 UTC 주차가 다를 수 있어 안내 시간을 통일한다. 동의 철회 시 설문·링크 기록 삭제, 계정 삭제 시 글·답글·신고·도움 요청까지 연쇄 삭제한다. 다른 사람의 요청에 응답한 계정이 삭제되면 응답자 연결이 비워진다.

`analyze.py`는 작은 표본에서 평균 변화 공개를 억제한다. 이 기능만으로 재식별 위험이 모두 해결되지는 않는다. 발표 전 원본 ID·날짜·모임 이름을 없애고 소수 집단 교차표를 내지 않는다. 실제 응답이 없는 현재는 0명/미측정으로 보고하며 예시 값을 연구 결과로 넣지 않는다.

## 아직 없는 것

푸시 알림, 실시간 채팅, 상담, 보육 위탁, 자동 지원금 자격 판정, 지리정보 자동 수집, 결제, 기관 관리자 웹 화면, 24시간 모니터링은 없다. 운영은 CLI로 수행한다. 배포 전 휴대폰에서 초대→글→응답→완료→철회 흐름을 실제 확인한다.
